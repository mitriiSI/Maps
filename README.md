# Форма · Maps

Веб-приложение для предпроектного анализа городской инфраструктуры и согласования планировочных решений со специалистом. Интерфейс на русском, адаптирован для компьютеров и телефонов.

## Что можно сделать

- Найти адрес или выбрать прямоугольный участок двумя кликами на карте; задать координаты вручную. Площадь — от 0,02 до 10 км².
- Загрузить инфраструктуру, здания и дороги OpenStreetMap через Overpass. Поиск адресов — Nominatim.
- Сравнить количество школ, детских садов, медицинских учреждений, зелёных зон, спортивных объектов, магазинов и остановок с расчётными ориентирами для заданного населения.
- Получить предварительные точки размещения, изометрический объёмный эскиз и объяснение каждого предложения.
- Передать эскиз на проверку, сохранить замечания и повторять цикл исправлений до одобрения.
- После одобрения разработать подробный проект каждого объекта: участок с размерами, функциональные зоны, здания и навесы, дорожки, посадки, скамьи, освещение, оборудование и концепцию пространства.
- Сравнить географическое положение контура, ближайший проезд, пешеходный подход и соседние здания. Переключаться между картой, изометрическим макетом и 3D-панорамой с уровня человека.
- Экспортировать генплан SVG, 3D-модель GLB, вид из панорамы PNG, автономный HTML-отчёт (с печатью в PDF) и JSON проекта со всей историей; импортировать JSON для продолжения работы.

Первый проект «Даниловский район» — **демонстрация на синтетических данных**, а не инвентаризация настоящего района. Для реальных данных создайте новую территорию.

## Запуск

Нужен Node.js 22 или новее.

```bash
npm ci
npm run dev
```

Сервер разработки доступен по адресу `http://localhost:5173`.

```bash
npm test          # проверки расчётов, согласования, автоправок и экспорта
npm run build    # TypeScript и production-сборка в dist/
npm run preview  # локальная проверка production-сборки
```

Приложение статическое: каталог `dist/` можно разместить на обычном веб-хостинге. Ключи API и серверная база данных не нужны. Подключение Sites описано в `.openai/hosting.json`.

## Как проходит согласование

```text
Участок → анализ и эскиз → проверка специалиста
                               ↓
                         есть замечания
                               ↓
                    исправленный эскиз и текст
                               ↓
                       повторная проверка
                               ↓
                           одобрение
                               ↓
                    детализированная концепция
```

Правки заблокированы на проверке и после одобрения. После замечания нужна новая версия — отправить прежнюю повторно нельзя. Для изменений в уже одобренном проекте откройте новую итерацию: старое одобрение перестанет действовать.

Простые команды автоматически меняют макет и пересчитывают обоснование:

```text
Перенеси детский сад на север
Перемести медицинский центр на запад
Добавь сквер на юге
Убери медицинский центр
```

Поддерживается одна команда с одним однозначно определяемым типом объекта и одним направлением. Если команду нельзя надёжно разобрать или свободная точка не найдена, замечание остаётся на доработке. Через «Уточнить эскиз» можно явно переместить, добавить, удалить объект или изменить требования. Автоправки основаны на правилах, внешняя языковая модель не подключена.

## Подробный проект и панорама

После одобрения нажмите **«Разработать проект»**. Под картой появится раздел подробного проектирования с переключением между объектами. Ранее сохранённые одобренные детализированные проекты обновляются автоматически; одобренные точки и история сохраняются.

Для парка создаются прогулочная петля и главная аллея, тихий сад, детская поляна, площадь встреч, дождевой сад, центральный луг, садовый павильон, пергола, игровой комплекс, фонтан, деревья, скамьи, светильники и велостойки. Для остальных категорий используются собственные программы: групповые корпуса и игровые дворы детсада, учебные крылья и спорт школы, амбулаторный и диагностический корпуса, спортивный двор, магазин с загрузкой, остановочный павильон.

В разделе объекта доступны:

- **Концепция** — идея, зонирование и характер пространства.
- **Состав** — площади, габариты, экспликация зон, объёмы зданий и оборудование.
- **Материалы** — покрытия, дерево, озеленение и металл.
- **Привязка** — координаты участка, ближайшая улица, подход и соседняя застройка.
- **Реализация** — этапы работ и условия дальнейшего проектирования.

Размеры задаются в метрах. Пятно подбирается внутри территории с учётом известных зданий, воды, парков, дорог и других проектируемых участков. При необходимости центр участка смещается относительно одобренного якоря, сохраняя якорь внутри контура. Если место слишком мало или препятствия не удаётся исключить, приложение показывает необходимость уточнения; вместимость не считается подтверждённой.

В **3D-панораме** тяните мышью или пальцем для осмотра, перемещайтесь клавишами WASD/стрелками или экранными кнопками. Колесо меняет угол обзора. Доступны точки обзора, мини-план с положением камеры, дневной/вечерний свет, полноэкранный режим и PNG. Камера избегает известных зданий, воды и стволов. Панорама — виртуальная прогулка по предлагаемому проекту, а не фотографическая съёмка.

Генплан, изометрия, панорама и GLB используют **одну модель данных**. GLB содержит здания, зоны, благоустройство и окружение OSM; единица — метр, X — восток, Y — высота, Z — юг. Географическая точка начала координат записана в метаданные сцены. Файл можно открыть в Blender и других 3D-программах. Панораме требуется WebGL; при его отсутствии остаются генплан и экспорт.

## Расчёт и размещение

Для каждой категории:

```text
ориентир = max(1, ceil(население / 1000 × коэффициент))
дефицит = max(0, ориентир − число объектов)
```

Коэффициенты и ориентиры доступности открыто заданы в `src/engine.ts` (`CATEGORIES`). Соотношение меньше 1 считается дефицитом, от 1 до 1,3 — балансом, больше 1,3 — превышением ориентира. Это эвристики приложения, **не утверждённые градостроительные нормативы**. Превышение ориентира не означает необходимость сноса.

Кандидаты размещения формируются внутри участка. Исключаются известные контуры зданий, парков, воды и буферы дорог. Рейтинг учитывает расстояние до аналогичных объектов, близость застройки, границы участка и запас места для последующего проектирования. Предлагается одна точка на дефицитную категорию — она не обязательно устраняет весь дефицит. Если подходящих точек нет, предложение не формируется.

## Хранение и передача специалисту

Все проекты и их версии сохраняются **в localStorage текущего браузера**. Аккаунтов, подтверждения личности специалиста, серверной синхронизации и автоматических уведомлений нет. Имя проверяющего вводится вручную; одобрение не является электронной подписью.

Для передачи:

1. Экспортируйте JSON и передайте его специалисту.
2. Специалист импортирует файл через «Мои проекты» → «Импорт JSON», вводит имя и решение на вкладке «Проверка».
3. Экспортированный им JSON импортируется обратно автором с заменой локальной копии того же проекта.

Не работайте одновременно в нескольких копиях: автоматического объединения изменений нет. Экспортируйте резервные копии, особенно перед очисткой данных браузера. При ошибке сохранения приложение показывает предупреждение.

## Ограничения

- OSM может содержать неполные или устаревшие данные; отсутствие объекта в OSM не доказывает его отсутствие на местности.
- Население задаёт пользователь. Модель считает объекты, а не их фактическую вместимость, качество или загрузку.
- Расстояния измеряются по прямой; пешеходные маршруты, барьеры, изохроны и транспортные потоки не рассчитываются.
- Доступность земли, кадастр, ПЗЗ, охранные/санитарные зоны, инсоляция и инженерные мощности не подтверждены.
- Подробный проект представляет архитектурную и ландшафтную концепцию с геометрией. Неизвестные высоты и ширины улиц условные; границы нового участка, габариты и вместимость — проектные допущения. GLB — пространственная модель; инженерная рабочая документация, CAD/BIM и разрешение на строительство не формируются.
- При недоступности внешнего сервиса отображается ошибка; реальные данные не заменяются скрытно демонстрационными.

До реализации необходима профессиональная проверка исходных данных и проектирование по применимым местным требованиям.

## Структура

| Файл                      | Назначение                                                        |
| ------------------------- | ----------------------------------------------------------------- |
| `src/App.tsx`             | Рабочее пространство и согласование                               |
| `src/engine.ts`           | Анализ, размещение, версии и автоправки                           |
| `src/data.ts`             | Nominatim / Overpass и нормализация OSM                           |
| `src/MapView.tsx`         | Карта и географические контуры участков                           |
| `src/Schematic.tsx`       | Изометрический макет и приближение к объектам                     |
| `src/design.ts`           | Метрические генпланы, концепции, подбор пятна и миграция проектов |
| `src/SitePlan.tsx`        | Генплан с размерами и окружением                                  |
| `src/DesignWorkspace.tsx` | Концепции, спецификация, материалы и привязка                     |
| `src/scene.ts`            | Общая трёхмерная геометрия инфраструктуры и окружения             |
| `src/Panorama.tsx`        | WebGL-прогулка, управление, точки обзора и PNG                    |
| `src/modelExport.ts`      | Экспорт пространственного проекта в GLB                           |
| `src/report.tsx`          | Полный автономный отчёт с генпланами                              |
| `src/storage.ts`          | Хранение, проверка и обмен JSON                                   |
| `tests/engine.test.ts`    | Проверки расчётов и согласования                                  |
| `tests/design.test.ts`    | Проверки генпланов, семи категорий, границ, миграций и отчёта     |

Технологии: React, TypeScript, Vite, Leaflet, Three.js, Lucide.
